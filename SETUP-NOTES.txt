Peekapoo Zone Puppies invoice app - Supabase-connected build

Supabase project URL and publishable key are configured in peekapoo-invoice-app.html.
The publishable key is safe for browser use. Do not add a service_role or secret key to this file.

FIRST-TIME SETUP (required before sign-in):
1. Open the Supabase project dashboard.
2. Open SQL Editor > New query.
3. Open SUPABASE-SETUP.sql from this ZIP, copy its entire contents, paste into SQL Editor, and click Run.
4. In Authentication > Users, create the first team user with an email and a temporary password. Create additional team members there too. Do not enable public sign-ups for this private business app.
5. Download/unzip this folder and open peekapoo-invoice-app.html in Chrome or Edge while connected to the internet.
6. Sign in using the email and password created in Supabase.
7. On the first sign-in, if this browser already has local invoices, the app asks whether to upload them to the shared database. Choose Upload to migrate these invoices. This initial migration only uploads the data currently saved in this browser; import any other computer's backup separately before using the shared app.

HOW IT WORKS:
- Signed-in users share one invoice dataset in Supabase.
- New, edited, deleted invoices and folder changes sync to Supabase when saved.
- Deleting a folder moves its invoices to No folder; it does not delete invoices.
- Change password asks for the current password and then the new password.
- Export backup remains available. Keep regular backups.
- The optional synced-folder button remains as a local file backup feature; Supabase is the shared source of truth.

IMPORTANT:
- Create team accounts manually in Supabase Authentication > Users. Do not enable public user registration.
- RLS policies allow every authenticated project user to read and edit the shared invoice data. Only create accounts for trusted team members.
- This app currently stores the shared invoices as one JSON payload. Avoid simultaneous edits to the same invoice from multiple computers; the most recently saved complete dataset wins.
- For password reset links, configure the Supabase Authentication URL settings if you later add a reset flow.
- The app needs an internet connection to sign in and sync. It can still keep a local browser cache, but local-only edits made while signed out are not shared.

EMAIL VERIFICATION CODE STEP (added in this build):
1. In Supabase Dashboard, open Authentication > Email Templates.
2. Open the Magic Link template. Change the email body so it includes the one-time token, for example:
   Your Peekapoo Zone Puppies verification code is: {{ .Token }}
   This code expires shortly. If you did not request it, ignore this email.
3. Save the template. The app first checks the account password, then sends an email OTP and requires the user to enter it before opening the invoice screen.
4. Test with a real team email address. If messages do not arrive, check Authentication email/SMTP settings and spam folders.

SECURITY NOTE:
The email code is an additional application login gate layered on top of Supabase password sign-in. Supabase's standard email OTP is not the same as a native email MFA factor enforced by Supabase Row Level Security. For stronger backend-enforced MFA, configure a supported Supabase MFA factor (such as an authenticator-app TOTP factor) and enforce the required assurance level in database policies.

LOGIN SECURITY GATE
- The dashboard, invoice list, folders, customer names, puppy names, and invoice values stay hidden until the user completes the email-code and password checks.
- The app sends a Supabase email OTP first without starting a password-authenticated session. After the code is verified, it checks the password. Only then does it load local/synced invoice data and the shared cloud database.
- The verification state is memory-only; refreshing or reopening the app requires email, password, and a fresh code again.
- Email delivery uses the Supabase Auth email provider. To have Resend deliver the codes, configure Resend as the custom SMTP provider in Supabase Auth settings after verifying a sending domain. Resend has not been independently connected by this app ZIP.

PRIVATE DATA / ACCESS CONTROL UPDATE:
- Re-run the included SUPABASE-SETUP.sql in the Supabase SQL Editor. It explicitly revokes all table privileges from PUBLIC and anon, and grants only SELECT/INSERT/UPDATE to authenticated users.
- Row Level Security remains enabled and every policy requires auth.uid() to be present. Anonymous visitors using only the publishable key cannot read or change invoice data.
- The app now fails closed visually: while locked, the sign-in gate is the only visible page element. It does not load local cache, synced-folder data, or cloud invoices until the login flow is complete.
- Supabase auth sessions are kept in memory only (not persisted in browser storage). Refreshing/reopening requires the full login flow again.
- Keep public sign-ups disabled and create only trusted team accounts in Supabase Authentication > Users. Anyone you add as an authenticated user can access and edit the shared invoice dataset.
- Important limitation: the email OTP step in this app is an application-level gate. Supabase RLS currently enforces authenticated password sessions, not the email OTP as a server-side MFA factor. For strict backend enforcement of all three factors, a separate server-verified OTP/MFA implementation must be deployed before treating email-code verification as backend-enforced MFA.
- Do not publish invoice backups, exported JSON files, or local browser profile data. The HTML app contains a publishable key, which is expected to be public; it does not contain a service-role key or invoice records.
